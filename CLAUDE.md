# Foxboard: rules for Claude

- Single file app: everything lives in `index.html` (inline CSS/JS). No frameworks, no build step, no CDNs except Google Fonts.
- The live copy is the Claude artifact `408d3d4e-8800-4a0e-9cdc-1251d2b400a7`. After changing `index.html`, republish it (cloud sessions: the Artifact tool, `url` https://claude.ai/code/artifact/408d3d4e-8800-4a0e-9cdc-1251d2b400a7, `file_path` index.html; a first publish in a session is refused once and hands back the live diff, then goes through) and commit here. Done means both: on main and live.
- Declared artifact capabilities: `downloads`, `sample` (images), `artifact`, `mcp` (connector `github`, tools `create_or_update_file`, `get_file_contents`), `db` (rules: `bible` read view / write admin; `toclaude` + `diag` read admin / write self with `toclaude/{self}` + `diag/{self}` read view / write interact, i.e. each person writes only under their own user id and only Duff/Editors read across; `fromclaude` + `fromclaudechunks` read view / write admin), `user` (scope profile). Gaining a capability: declare first, then publish. Losing one: publish first, then declare. Every redeclare must list ALL of them.
- `artifact` stores user templates in `templates/library.json` on the artifact. Never overwrite or delete that file from here.
- `db` holds the shared library (`library/<id>` meta + `libchunks/<id>_<n>` body chunks under 180k chars, `libnotes/<id>`) and the style bible (`bible/main`). The bible's built-in default lives in `DEFAULT_BIBLE` in index.html; the db copy wins once Duff saves.
- Send to game, default path (Nov 18): the page queues art in the db outbox (`outbox/<id>` meta with sha256 + `outboxchunks/<id>_<n>` base64 chunks). The scheduled task "Foxboard outbox sweep" (every 4 h, auto-approve) delivers it with git per `SWEEP.md`; any chat can run SWEEP.md on request. Sweeps never delete db rows (that needs Duff's approval): they blank delivered chunks. Verified live Nov 18 on lethemoor.
- Send to game, direct path (bible toggle per game, off by default): commits `<inbox>/<date>-foxboard/<name>-<HHMMSS>.<png|gif>.b64` to the game repo's main through the viewer's GitHub connector (text only, hence base64). Each game repo needs `.github/workflows/foxboard_decode.yml` + `grok_art/**` in build.yml's paths-ignore. Lethemoor has it (verified live Nov 18). DuffQuest: apply `integrations/duffquest-foxboard-inbox.patch` in a DuffQuest session, then flip its decoder on in the bible. The connector only sees PUBLIC repos until Duff grants the Claude GitHub app access to private ones.
- Duff is phone-only (Android). Every feature must work by touch on a ~390px-wide screen. No desktop-only steps.
- Madison and Brittany (iPhone/Safari) may use it too: test that features degrade gracefully when `window.claude` is absent.
- Built-in templates and AI prompts must stay original: no copyrighted characters or logos.
- Run every script in `tests/` before shipping: `tools/claude/check.sh` does all of it (Chromium, then WebKit, then 390px screenshots in /tmp/foxboard-shots — Read them). New tests must be seen failing once before they count.
- Forge (Nov 19): ✨AI › Forge commits `forge/jobs/<id>.json` here via the GitHub connector; `.github/workflows/forge.yml` renders each version on its own free runner (FLUX.1-schnell q4 + T5 q8 gguf, stable-diffusion.cpp, ~15 min at 768) and commits `forge/results/<id>/<k>.png` + `<k>.b64` (`png:`/`webp:` + base64, <1 MB so the connector can read it) + `done.json`. Needs this repo PUBLIC (free 4 vCPU/16 GB runners). Key-color jobs get their background forced to the exact key (`forge/keyfix.py`: border flood plus enclosed key-tinted patches like shadow between legs; muted subject colors survive). Prompts and outputs are public.
- Claude access (Nov 19): every feature is scriptable through `window.Foxboard` (`Foxboard.help()` lists it). Claude runs it headless with `node tools/claude/fb.js script.js` (see tools/claude/README.md), builds Forge jobs with `Foxboard.forgeFiles` and commits them, and moves docs in and out of the shared library with `fbx.py` + the artifact db tools. Any new feature must get an API command and a line in `API_DOC`.
- Forge modes: `new`, `sketch` (img2img from the whole init, `strength` 0.5-0.95, default 0.87, lower = closer; below ~0.75 FLUX schnell leaves a flat sketch flat (runner A/B Nov 19); take variations use subtle 0.6 / strong 0.8, seed kept), `edit` (Magic edit, Nov 19: FLUX.2 klein 4B Apache-2.0 edit model via `forge/magic_edit.py`: crops around the mask, edits with the crop as reference image, pastes back through a feathered mask, keeps original alpha; ~8 min at side 512. Schnell inpaint scribbled junk, don't go back), `bg` (app-side: an `edit` whose mask is the cut-out's transparent area), `expand` (outpaint), `upscale` (RealESRGAN anime x4, Lanczos fallback). `tile:true` adds sd.cpp `--circular` (seamless). `seed` is honored (take k uses seed+k). `FORGE_DRY=1 python forge/render_one.py <job> <k>` prints the sd command without rendering (tests use it). Inputs go in `forge/jobs/<id>.init.b64` / `.mask.b64` (`png:`/`jpg:` + base64).
- Look (Nov 19): fox night-forest theme from Duff's phone theme: bg #0b0c12, midnight panels #121a2a/#1a2438, russet fox accent #c2602f, lantern amber #f0a040 highlights/selection, teal #2f6e73, moonlight text #dae0e5, Cinzel for titles. Keep it restrained (gold-on-black, no clutter). Test new screens in WebKit (iPhone) too: `BROWSER=webkit APP_URL=http://localhost:PORT/index.html python3 tests/...`.
- Installable copy for Madison/Brittany (iPhone home screen): `python3 tools/build_site.py` builds `site/` (icons, manifest, offline worker) from index.html; rebuild it after every index.html change, push, then purge jsDelivr (`curl -s https://purge.jsdelivr.net/gh/duffpowell-commits/Foxboard@main/site/index.html`). The public link https://foxboard-gamma.vercel.app (Vercel project foxboard) is a tiny loader (`site/host/`) that pulls `site/index.html` from jsDelivr, so it only needs redeploying if `site/host/` changes. Claude-only parts show a note there instead of failing.
- Audit fixes (Nov 19): outbox rows are written meta-first as `status:"uploading"`, then chunks, then flipped to `queued` (a failed upload deletes its own rows); library deletes go notes → chunks → meta; template saves re-read and merge the cloud `templates/library.json` and never publish when it can't be read; bible edits are held while the sheet is open and a live snapshot is applied on close. `__fb.t` exposes internals for `tests/test_audit_fixes.py`. Known gap: db rules can't limit library deletes to the sharer (doc ids aren't user ids), so any Editor can delete library rows by script.
- Creative tools (Nov 19): Forge screen has Start from (new / my sketch = this frame / selected image) + Follow slider, Seamless tile, 🔒 Seed, ✨ Boost prompt (sample, hidden without Claude); tapping a take shows ➕ Add / 🔁 Subtle / 🎲 Strong / ☆ Favorite / ♻ Reuse (prompt + seed); Jobs / All takes / ⭐ Favorites views. Image panel: 👾 Pixelate (size, palette, outline; sets `px` so it draws crisp), 🧩 Make seamless + ▦ 3×3 preview, sticker outline, 🌄 New background, ◐ before/after vs the layer below. All in `API_DOC`; tested by `tests/test_creative.py`.
- Claude link (Nov 19): Menu › 📨 Send to Claude writes `toclaude/<userId>/items/<id>` (note, PNG snapshot, layer list, `status` uploading→sent) + `toclaude/<userId>/chunks/<id>_<n>` (doc JSON), plus a marker doc `toclaude/<userId>`. List `toclaude` for user ids, then read `toclaude/<uid>/items` + `/chunks` with ArtifactData (out_dir), unpack with `fbx.py inbox <id> <db_dir> OUTDIR`, then update the row `{status:"seen", reply:"..."}` (Duff sees the reply in that sheet; only his own rows can be written, other people's are read-only even for him). Drafts back: `fbx.py push-draft doc.json preview.png OUTDIR --title T --note N`, send writes.json batches in order; the page shows an "Open" banner and loads it as data (never code), undoable. Problems: every failure + uncaught error goes to the phone's log and, inside Claude, to `diag/<userId>/log/` (kind, msg, code, stack, ua, ver; list `diag` for user ids) — read it when Duff says something broke. Never delete these rows without Duff's OK.
- Forge waits: queue, then run `python3 tools/claude/forge_wait.py <id>...` with Bash run_in_background: it sleeps to the ETA, then exits when done.json lands (0), a job looks stuck (2: way past ETA and Forge delivered nothing for anyone in 30 min — a busy queue is not stuck) or it times out (3) — the exit wakes the session. GitHub can't wake a session directly; across sessions use send_later.
