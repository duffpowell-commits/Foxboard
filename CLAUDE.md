# Foxboard: rules for Claude

- Single file app: everything lives in `index.html` (inline CSS/JS). No frameworks, no build step, no CDNs except Google Fonts.
- The live copy is the Claude artifact `408d3d4e-8800-4a0e-9cdc-1251d2b400a7`. After changing `index.html`, republish it (cloud sessions: the Artifact tool, `url` https://claude.ai/code/artifact/408d3d4e-8800-4a0e-9cdc-1251d2b400a7, `file_path` index.html; a first publish in a session is refused once and hands back the live diff, then goes through) and commit here. Done means both: on main and live.
- Declared artifact capabilities: `downloads`, `sample` (images), `artifact`, `mcp` (connector `github`, tools `create_or_update_file`, `get_file_contents`), `db` (rules: `bible` read view / write admin; `toclaude` + `diag` read admin / write self with `toclaude/{self}` + `diag/{self}` read view / write interact, i.e. each person writes only under their own user id and only Duff/Editors read across; `fromclaude` + `fromclaudechunks` read view / write admin), `user` (scope profile). Gaining a capability: declare first, then publish. Losing one: publish first, then declare. Every redeclare must list ALL of them.
- `artifact` stores user templates in `templates/library.json` on the artifact. Never overwrite or delete that file from here.
- `db` holds the shared library (`library/<id>` meta + `libchunks/<id>_<n>` body chunks under 180k chars, `libnotes/<id>`) and the style bible (`bible/main`). The bible's built-in default lives in `DEFAULT_BIBLE` in index.html; the db copy wins once Duff saves.
- Send to game, default path (Nov 18): the page queues art in the db outbox (`outbox/<id>` meta with sha256 + `outboxchunks/<id>_<n>` base64 chunks). The scheduled task "Foxboard outbox sweep" (every 4 h, auto-approve) delivers it with git per `SWEEP.md`; any chat can run SWEEP.md on request. Sweeps never delete db rows (that needs Duff's approval): they blank delivered chunks. Verified live Nov 18 on lethemoor, and again end to end Nov 20 (real cut-out Forge sprite → outbox → sweep → lethemoor 79968a1, SHA-256 identical on GitHub; test file removed in 243dbab). The sweep task's prompt now opens with a tool allowlist (GUARDS).
- Send to game, direct path (bible toggle per game, off by default): commits `<inbox>/<date>-foxboard/<name>-<HHMMSS>.<png|gif>.b64` to the game repo's main through the viewer's GitHub connector (text only, hence base64). Each game repo needs `.github/workflows/foxboard_decode.yml` + `grok_art/**` in build.yml's paths-ignore. Lethemoor has it (verified live Nov 18). DuffQuest: apply `integrations/duffquest-foxboard-inbox.patch` in a DuffQuest session, then flip its decoder on in the bible. The connector only sees PUBLIC repos until Duff grants the Claude GitHub app access to private ones.
- Duff is phone-only (Android). Every feature must work by touch on a ~390px-wide screen. No desktop-only steps.
- Madison and Brittany (iPhone/Safari) may use it too: test that features degrade gracefully when `window.claude` is absent.
- Built-in templates and AI prompts must stay original: no copyrighted characters or logos.
- Run every script in `tests/` before shipping: `tools/claude/check.sh` does all of it (Chromium, then WebKit, then 390px screenshots in /tmp/foxboard-shots — Read them). New tests must be seen failing once before they count.
- Game art prompting (Nov 21): when you queue Forge jobs for Hunter or Lethemoor, follow `docs/ART_GENERATION_GUIDE.md`. Queue with `python3 tools/claude/art_loop.py queue` (it now accepts `--mode --init --mask --ref --strength --tile --seed --w/--h`) or `F.forgeFiles` + git. Job-only commits go straight to Foxboard `main` (that is what `forge.yml` renders); code still goes through a PR. `ref` is a style-board workaround, not IP-Adapter — see `docs/DECISIONS.md`. Prompts and outputs here are public: no private info. Duff likeness note (Nov 21, 2026): Duff explicitly okayed his likeness being public in this repo, so Claude may use, commit and generate Duff likeness art here.
- Forge (Nov 19): ✨AI › Forge commits `forge/jobs/<id>.json` here via the GitHub connector; `.github/workflows/forge.yml` renders each version on its own free runner (FLUX.1-schnell q4 + T5 q8 gguf, stable-diffusion.cpp, ~15 min at 768) and commits `forge/results/<id>/<k>.png` + `<k>.b64` (`png:`/`webp:` + base64, <1 MB so the connector can read it) + `done.json`. Needs this repo PUBLIC (free 4 vCPU/16 GB runners). Key-color jobs get their background forced to the exact key (`forge/keyfix.py`: border flood plus enclosed key-tinted patches like shadow between legs; muted subject colors survive). Prompts and outputs are public.
- Claude access (Nov 19): every feature is scriptable through `window.Foxboard` (`Foxboard.help()` lists it). Claude runs it headless with `node tools/claude/fb.js script.js` (see tools/claude/README.md), builds Forge jobs with `Foxboard.forgeFiles` and commits them, and moves docs in and out of the shared library with `fbx.py` + the artifact db tools. Any new feature must get an API command and a line in `API_DOC`.
- Forge modes: `new`, `sketch` (img2img from the whole init, `strength` 0.3-0.95, default 0.87, lower = closer; a flat sketch needs >=0.75 or FLUX schnell leaves it flat, so the Follow slider spans 0.75-0.95; take variations use subtle 0.35 (same layout) / strong 0.6 (reworked details), seed kept — runner A/Bs Nov 19), `edit` (Magic edit, Nov 19: FLUX.2 klein 4B Apache-2.0 edit model via `forge/magic_edit.py`: crops around the mask, edits with the crop as reference image, pastes back through a feathered mask, keeps original alpha; ~8 min at side 512. Schnell inpaint scribbled junk, don't go back), `bg` (app-side: an `edit` with `engine:"flux"` whose mask is the cut-out's transparent area — klein keeps alpha, so the scene came back transparent; FLUX fill at 0.92 verified on real art Nov 20, ~24 min at 512×1024), `expand` (outpaint; app default `engine:"klein"` — real-art A/B Nov 20: klein continued the picture, FLUX gave glassy edges at 0.78 / a seam + new texture at 0.9; ~8 min). `forge/engine.py` `uses_klein(job)` decides klein vs FLUX for both render_one.py and get_models.py, `upscale` (RealESRGAN anime x4, Lanczos fallback). `tile:true` adds sd.cpp `--circular` (seamless). `seed` is honored (take k uses seed+k). `FORGE_DRY=1 python forge/render_one.py <job> <k>` prints the sd command without rendering (tests use it). Each render is capped at 3x its expected time (min 25 min, `FORGE_TIMEOUT_MIN` overrides): a hung render becomes a failed take instead of blocking every session's queue. Inputs go in `forge/jobs/<id>.init.b64` / `.mask.b64` / `.ref.b64` (`png:`/`jpg:` + base64). `init` on `mode:"new"` is no longer ignored: the renderer and `art_loop.py queue` switch the job to `sketch` and warn. `ref` (plus `ref_strength`, default 0.55) is a style-board + img2img workaround for a new subject; it is not IP-Adapter (sd.cpp has no FLUX IP-Adapter). Cannot set `init` and `ref` on the same job. Sizes are 256-1024 and a multiple of 64. Job-only pushes to `main` under `forge/jobs/**` are allowed (that is how a job renders); enable `.githooks/pre-push` with `git config core.hooksPath .githooks` to block any other main push locally. Clean up takes with `art_loop.py score` and `art_loop.py cut`.

- Claude link (Nov 19): Menu › 📨 Send to Claude writes `toclaude/<userId>/items/<id>` (note, PNG snapshot, layer list, `status` uploading→sent) + `toclaude/<userId>/chunks/<id>_<n>` (doc JSON), plus a marker doc `toclaude/<userId>`. - Forge auto-send (Nov 23): a Forge job with `game` (`lethemoor`|`duffquest`, + `name`) gets each finished take dropped into that game repo's `grok_art/<date>-foxboard/<name>-<k>.png` by `forge/send_game.py` on the render runner (GitHub contents API, secret `GAME_PUSH_TOKEN` = fine-grained token, Contents read/write on the game repos). Never fails a take; the outcome is `forge/results/<id>/<k>.sent.json`. App: Forge › 📦 Auto-send takes to the game (needs a Game style); API `forge({...game,name})`; `art_loop.py queue --send-to`. Lethemoor's bible default is now `direct:true` (Send to game commits straight away, 404 falls back to the outbox). Tested by `tests/test_send_game.py`.
- Forge waits: queue, then run `python3 tools/claude/forge_wait.py <id>...` with Bash run_in_background: it sleeps to the ETA, then exits when done.json lands (0), a job looks stuck (2: way past ETA and Forge delivered nothing for anyone in 30 min — a busy queue is not stuck) or it times out (3) — the exit wakes the session. GitHub can't wake a session directly; across sessions use send_later.
