# Foxboard: rules for Claude

- Single file app: everything lives in `index.html` (inline CSS/JS). No frameworks, no build step, no CDNs except Google Fonts.
- The live copy is the Claude artifact `408d3d4e-8800-4a0e-9cdc-1251d2b400a7`. After changing `index.html`, republish it with publish_files (mode patch, `as: index.html`) and commit here. Done means both: on main and live.
- Declared artifact capabilities: `downloads`, `sample` (images), `artifact`, `mcp` (connector `github`, tools `create_or_update_file`, `get_file_contents`), `db` (rule: `bible` read view / write admin), `user` (scope profile). Gaining a capability: declare first, then publish. Losing one: publish first, then declare. Every redeclare must list ALL of them.
- `artifact` stores user templates in `templates/library.json` on the artifact. Never overwrite or delete that file from here.
- `db` holds the shared library (`library/<id>` meta + `libchunks/<id>_<n>` body chunks under 180k chars, `libnotes/<id>`) and the style bible (`bible/main`). The bible's built-in default lives in `DEFAULT_BIBLE` in index.html; the db copy wins once Duff saves.
- Send to game, default path (Nov 18): the page queues art in the db outbox (`outbox/<id>` meta with sha256 + `outboxchunks/<id>_<n>` base64 chunks). The scheduled task "Foxboard outbox sweep" (every 4 h, auto-approve) delivers it with git per `SWEEP.md`; any chat can run SWEEP.md on request. Sweeps never delete db rows (that needs Duff's approval): they blank delivered chunks. Verified live Nov 18 on lethemoor.
- Send to game, direct path (bible toggle per game, off by default): commits `<inbox>/<date>-foxboard/<name>-<HHMMSS>.<png|gif>.b64` to the game repo's main through the viewer's GitHub connector (text only, hence base64). Each game repo needs `.github/workflows/foxboard_decode.yml` + `grok_art/**` in build.yml's paths-ignore. Lethemoor has it (verified live Nov 18). DuffQuest: apply `integrations/duffquest-foxboard-inbox.patch` in a DuffQuest session, then flip its decoder on in the bible. The connector only sees PUBLIC repos until Duff grants the Claude GitHub app access to private ones.
- Duff is phone-only (Android). Every feature must work by touch on a ~390px-wide screen. No desktop-only steps.
- Madison and Brittany (iPhone/Safari) may use it too: test that features degrade gracefully when `window.claude` is absent.
- Built-in templates and AI prompts must stay original: no copyrighted characters or logos.
- Run every script in `tests/` before shipping. New tests must be seen failing once before they count.
- Forge (Nov 19): ✨AI › Forge commits `forge/jobs/<id>.json` here via the GitHub connector; `.github/workflows/forge.yml` renders each version on its own free runner (FLUX.1-schnell q4 + T5 q8 gguf, stable-diffusion.cpp, ~15 min at 768) and commits `forge/results/<id>/<k>.png` + `<k>.b64` (`png:`/`webp:` + base64, <1 MB so the connector can read it) + `done.json`. Needs this repo PUBLIC (free 4 vCPU/16 GB runners). Key-color jobs get their border background forced to the exact key. Prompts and outputs are public.
